APIkit for SOAP simplifies building and integrating SOAP-based web services by handling message formats, headers, and WSDL binding against your existing SOAP endpoints. SOAP (Simple Object Access Protocol) exchanges structured payloads between services. APIkit for SOAP keeps those payloads aligned with your contracts. To learn more about automated configurations, data transformations, XML 1.0 defaults, and optional XML 1.1 C0 characters, see xref:apikit-for-soap-module-reference.adoc#apikit-for-soap-system-properties[system property].

== Supply Spring to Apply cxf.xml

APIkit for SOAP 3.0.0 supports Spring 7 and doesn't bundle Spring. The module uses the Spring bus when the application provides Spring 7. Otherwise, it uses the CXF bus, and a `cxf.xml` file in the application isn't applied.

Add Spring Framework 7 (`org.springframework:spring-context`) as a shared library when you upgrade to 3.0.0 and the application relies on `cxf.xml`. For setup steps, see xref:mule-runtime::mmp-concept.adoc#configure-shared-libraries[Configure Shared Libraries].

Applications that don't use `cxf.xml` can run 3.0.0 without Spring. APIkit for SOAP 2.x still bundles Spring, so `cxf.xml` continues to apply on that line without a shared library.

== APIkit for SOAP Features

* Streamlines SOAP API development, ensuring seamless integration with your existing SOAP infrastructure.
* Simplifies the handling of SOAP message formats and headers, so you can focus on the core logic of your APIs. 
* Automates the binding to WSDL (Web Services Description Language), reducing manual configuration efforts and ensuring accuracy.
* Supports data transformations.
* Defines and exposes SOAP APIs with ease by emphasizing SOAP/WSDL contracts. 
* Supports XML 1.0 characters by default. Supports XML 1.1 C0 characters through the xref:apikit-for-soap-module-reference.adoc#apikit-for-soap-system-properties[system property].
