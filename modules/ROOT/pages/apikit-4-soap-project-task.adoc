= Create an APIkit for SOAP Project
ifndef::env-site,env-github[]
include::_attributes.adoc[]
endif::[]

Create a Mule project from a WSDL so Anypoint Studio generates APIkit for SOAP flows and stores the contract under `src/main/resources/api`. Meet the xref:apikit-4-soap-prerequisites-task.adoc[prerequisites for using APIkit for SOAP] first. After you pick the service and port, run the application and retrieve the published WSDL from the HTTP endpoint to verify the service.

. In Anypoint Studio, from *File*, select *New* > *Mule Project*.
+
image::create-new-mule-project-soap.png["New Mule project window that highlights the project-name field, runtime engine, *From Design Center or Local Files* tab, and expand icon for browsing files"]

[calloutlist]
. In *Project Name*, enter a name for the project. +
For example, `soap-implementation`.
. Select the Mule runtime engine version. +
For example, `Mule Server 4.2.2 EE`.
. In *API Specification*, select *From Design Center or Local Files*.
. Select *Browse files* from the *More actions* menu.

[start=2]
. Select a service and port. For this example, accept the default values, `TshirtService` and `TshirtServicePort`.
+
image::create-apikit-soap-project.png["API specification window that highlights the service and the port from the menu"]
+
. Click *Finish*.
+
The new project appears with the WSDL file in the `src/main/resources/api` folder.
. Right-click a blank area of the canvas and select *Run Project*.
. In your SOAP UI client, go to `+http://localhost:8081/TshirtService/TshirtServicePort?wsdl+`.
+
The SOAP service returns the content of your WSDL file.

If you update your WSDL file, regenerate your flows by right-clicking your WSDL file and selecting *Mule* > *Generate Flows From WSDL*.
